# Tasks REST API — Assignment 6

A RESTful API for managing **tasks** (a to-do list), built with **Node.js**, **Express 5** and a **SQLite** database.

- Full CRUD on one resource: `tasks`
- Data is stored in a real SQLite database file (`data/tasks.db`), so it survives server restarts
- Input validation with clear JSON error messages
- Correct status codes: `200`, `201`, `400`, `404`, `500`
- Postman collection and automated tests included

## Requirements

- Node.js 22.13 or newer (check with `node --version`)
- npm

No database server is needed: SQLite is a file, and it is created automatically on first start. The API uses Node's built-in `node:sqlite` module, so there is no native package to compile. On Node 22, Node prints an `ExperimentalWarning` about SQLite at startup; it is harmless.

## How to run

```bash
# 1. Install dependencies
npm install

# 2. Create your .env file from the example
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env

# 3. (Optional) insert 3 sample tasks
npm run seed

# 4. Start the server
npm start
```

The server prints:

```
Tasks API listening on http://localhost:3000
SQLite database: .../data/tasks.db
```

Open <http://localhost:3000/tasks> in a browser to check that it works.

Other scripts:

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the server and restart it when a file changes |
| `npm run seed` | Insert sample tasks (only if the table is empty) |
| `npm test` | Run the automated tests |
| `npm run test:postman` | Run the Postman collection with Newman (server must be running) |

## Environment variables

Configuration is read from a `.env` file. This file is listed in `.gitignore` and is **not** committed. `.env.example` shows the available variables:

| Variable | Default | Description |
| --- | --- | --- |
| `PORT` | `3000` | Port the server listens on |
| `DB_FILE` | `./data/tasks.db` | Path to the SQLite database file |

If port 3000 is already used on your machine, set another one in `.env` (for example `PORT=3055`).

## The task resource

| Field | Type | Rules |
| --- | --- | --- |
| `id` | integer | Generated by the database, read-only |
| `title` | string | **Required**, 1–100 characters |
| `description` | string | Optional, at most 1000 characters. Default `""` |
| `status` | string | Optional: `todo`, `in_progress` or `done`. Default `todo` |
| `priority` | string | Optional: `low`, `medium` or `high`. Default `medium` |
| `dueDate` | string or null | Optional, a real date in `YYYY-MM-DD` format. Default `null` |
| `createdAt` | string | ISO timestamp, set by the server, read-only |
| `updatedAt` | string | ISO timestamp, set by the server, read-only |

Fields that are not in this table are rejected with a `400`.

## Routes

Base URL: `http://localhost:3000`

| Method | Route | Description | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/tasks` | List all tasks | 200 | 400 |
| GET | `/tasks/:id` | Get one task | 200 | 400, 404 |
| POST | `/tasks` | Create a task | 201 | 400 |
| PUT | `/tasks/:id` | Replace a task | 200 | 400, 404 |
| PATCH | `/tasks/:id` | Update some fields of a task | 200 | 400, 404 |
| DELETE | `/tasks/:id` | Delete a task | 200 | 400, 404 |
| GET | `/health` | Check the server and database | 200 | |
| GET | `/` | API name and list of routes | 200 | |

All requests with a body must send the header `Content-Type: application/json`.

The curl examples below use bash quoting. On Windows, run them in Git Bash, or use the Postman collection.

### GET /tasks — list all tasks

Optional query filters:

| Parameter | Example | Description |
| --- | --- | --- |
| `status` | `?status=done` | Only tasks with this status |
| `priority` | `?priority=high` | Only tasks with this priority |
| `q` | `?q=readme` | Only tasks whose title or description contains this text |

curl http://localhost:3000/tasks
curl "http://localhost:3000/tasks?status=in_progress&priority=high"

  }

### POST /tasks — create a task

```bash
curl -i -X POST http://localhost:3000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Finish assignment 6","description":"REST API with Express and SQLite","status":"in_progress","priority":"high","dueDate":"2026-11-20"}'
```

Request body (only `title` is required):

```json
{
  "title": "Finish assignment 6",
  "description": "REST API with Express and SQLite",
  "status": "in_progress",
  "priority": "high",
  "dueDate": "2026-11-20"
}
```

Response `201 Created`, with the header `Location: /tasks/4`:

```json
{
  "data": {
    "id": 4,
    "title": "Finish assignment 6",
    "description": "REST API with Express and SQLite",
    "status": "in_progress",
    "priority": "high",
    "dueDate": "2026-11-20",
    "createdAt": "2026-11-10T17:57:22.512Z",
    "updatedAt": "2026-11-10T17:57:22.512Z"
  }
}
```

Response `400 Bad Request` (invalid data — one message per invalid field):

```bash
curl -X POST http://localhost:3000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"","status":"finished"}'
```

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid task data",
    "details": [
      { "field": "title", "message": "title must not be empty" },
      { "field": "status", "message": "status must be one of: todo, in_progress, done" }
    ]
  }
}
```

Response `400 Bad Request` (the body is not valid JSON):

```json
{
  "error": {
    "code": "INVALID_JSON",
    "message": "Request body is not valid JSON"
  }
}
```

### PUT /tasks/:id — replace a task

`PUT` replaces the whole task. `title` is required, and optional fields that are not sent go back to their default values. To change only some fields, use `PATCH`.

```bash
curl -X PUT http://localhost:3000/tasks/4 \
  -H "Content-Type: application/json" \
  -d '{"title":"Finish and submit assignment 6","description":"Push to GitHub and upload the zip","status":"done","priority":"medium","dueDate":"2026-11-21"}'
```

Request body:

```json
{
  "title": "Finish and submit assignment 6",
  "description": "Push to GitHub and upload the zip",
  "status": "done",
  "priority": "medium",
  "dueDate": "2026-11-21"
}
```

Response `200 OK`:

```json
{
  "data": {
    "id": 4,
    "title": "Finish and submit assignment 6",
    "description": "Push to GitHub and upload the zip",
    "status": "done",
    "priority": "medium",
    "dueDate": "2026-11-21",
    "createdAt": "2026-11-10T17:57:22.512Z",
    "updatedAt": "2026-11-10T17:57:22.630Z"
  }
}
```

Errors: `400` for invalid data or an invalid id, `404` if the task does not exist (same format as above).

## Errors and status codes

Every error is returned as JSON in the same shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid task data",
    "details": [{ "field": "title", "message": "title is required" }]
  }
}
```

`details` is only present for validation errors.

| Status | `code` | When |
| --- | --- | --- |
| 200 | | Successful GET, PUT, PATCH, DELETE |
| 201 | | Task created |
| 400 | `VALIDATION_ERROR` | Invalid field, unknown field, missing body, invalid id, invalid query filter |
| 400 | `INVALID_JSON` | The request body is not valid JSON |
| 404 | `NOT_FOUND` | The task does not exist, or the route does not exist |
| 500 | `INTERNAL_ERROR` | Unexpected server error (the details are logged on the server, not sent to the client) |

All errors go through one error-handling middleware (`src/middleware/errors.js`), so malformed input or a missing record never crashes the server.

## Testing

### Postman collection

`postman/Tasks-API.postman_collection.json` contains 18 requests that cover every route, including the error cases. Each request has test scripts that check the status code and the response.

1. Start the server: `npm start`
2. In Postman: **Import** → select the collection file
3. Run the requests in order (or use **Run collection**). "Create task" saves the new id in the `taskId` variable used by the later requests.

The collection uses the variable `baseUrl` (default `http://localhost:3000`).

It can also be run from the command line with Newman:

```bash
npm run test:postman
```

### Automated tests

```bash
npm test
```

17 tests (Node's built-in test runner + supertest) call every route against a temporary SQLite file.
